# 意拍 IntentShot｜产品需求文档（PRD）

**版本：** v1.0  
**状态：** 产品定义 / MVP 规划  
**平台：** iOS（首发）  
**品牌：** 意拍 / IntentShot

---

## 1. 产品概述

### 1.1 一句话定义

意拍是一款自然语言驱动的 AI 智能相机：用户说出想拍出的画面，应用结合设备能力与现场环境，自动生成并应用拍摄方案，帮助用户更容易拍出接近预期的照片。

### 1.2 产品愿景

降低摄影参数和拍摄技巧的门槛，让用户把注意力放在“想拍什么”与“如何构图”上，而不是研究复杂的相机设置。

### 1.3 核心价值主张

> 说出你想拍的，剩下的交给意拍。

产品不是单纯的摄影教学、参数推荐或照片后期工具，而是形成“意图理解—场景分析—相机配置—实际拍摄—效果反馈”的闭环。

### 1.4 产品边界

- 意拍是独立相机应用，不是通用 AI 助手。
- 首期重点是拍摄前和拍摄中的相机配置与辅助，不承诺完全控制 iOS 原生相机的所有能力。
- 系统只使用公开、可用的 API 和设备运行时能力；无法控制的成像算法或硬件能力不作保证。
- 生成式后期编辑、社交社区、完整专业视频制作不属于 MVP 核心范围。

## 2. 用户与使用场景

### 2.1 目标用户

1. **日常拍摄用户**：知道想要什么效果，但不了解曝光、对焦、镜头等参数。
2. **轻度摄影爱好者**：希望更快获得稳定效果，不想每次从头调参。
3. **内容创作者**：需要反复拍摄人像、美食、产品或生活场景，希望保存和复用方案。

### 2.2 核心场景

- 人像：人物清晰、脸部明亮、背景虚化、氛围感。
- 美食/静物：主体突出、暖色调、背景简洁。
- 旅行与风景：构图、光线、色彩和场景氛围。
- 夜景：在设备能力允许范围内平衡清晰度、亮度和噪点。
- 视频：后续版本探索，首期不作为核心承诺。

### 2.3 Jobs To Be Done

> 当我想拍出某种效果、却不知道相机该怎么设置时，我希望只需描述目标，应用就能帮我配置相机并指导我完成拍摄，让我更少试错地获得满意照片。

## 3. 产品体验与用户旅程

### 3.1 主流程

1. 打开意拍，进入取景器。
2. 点击“描述想拍的画面”或选择一个场景模板。
3. 输入自然语言，例如：“拍一张人物清晰、背景虚化、脸部明亮的电影感人像。”
4. 应用解析意图，结合设备能力和实时画面生成拍摄方案。
5. 用户查看方案摘要，点击“应用方案”。
6. 进入取景器，系统执行可支持的参数配置并显示必要提示。
7. 用户构图并按下快门。
8. 应用展示照片及目标达成反馈。
9. 用户可以说“背景再暗一点”或“人物往中间一些”，系统生成局部调整方案。
10. 用户保存照片，并可保存或复用拍摄方案。

### 3.2 关键体验原则

- 用户始终可以拍摄，不被 AI 流程锁死。
- 自动调整要可感知、可撤销，避免参数无提示地跳动。
- 用户明确锁定的参数和目标，不应被系统随意覆盖。
- 复杂或互相冲突的需求应解释限制，并给出可执行的折中方案。
- 取景器是核心工作区，AI 对话不应长期遮挡画面。

## 4. 功能需求（Functional Requirements）

### FR-01｜自然语言拍摄需求输入
用户可通过文本输入描述拍摄目标；后续可评估语音输入。系统应支持中文常见摄影表达。

### FR-02｜意图结构化
将自然语言转换为统一的摄影意图对象，包括主体、风格、目标、优先级、约束和不确定项。输出必须通过 Schema 校验。

### FR-03｜需求冲突识别
识别无法同时满足的目标，例如“极暗环境、快速快门、完全无噪点”。系统应提出澄清问题或生成折中策略。

### FR-04｜场景与主体分析
分析实时取景中的人物、主体位置、亮度、逆光和构图等信息。复杂视觉分析按需触发，避免每帧运行重型模型。

### FR-05｜设备能力识别
运行时读取当前设备和拍摄会话支持的镜头、模式及参数能力。不得将某一机型的能力写死为所有设备通用。

### FR-06｜拍摄方案生成
根据意图、场景状态、设备能力和摄影规则生成方案，方案需说明目标、模式、镜头策略、对焦/曝光策略及限制。

### FR-07｜方案预览与应用
用户可以查看方案摘要后应用。系统应明确显示应用成功、部分应用或无法应用的项目。

### FR-08｜相机参数执行
通过公开相机 API 应用设备支持的参数。所有参数必须经过范围、模式兼容性和安全约束校验。

### FR-09｜取景器与构图辅助
提供取景画面、主体提示、必要的构图辅助和当前方案状态；辅助元素可关闭。

### FR-10｜拍照与预览
支持拍照、预览、重拍、保存和进入系统照片库（权限按系统要求申请）。

### FR-11｜拍摄后质量分析
对主体清晰度、曝光、构图、景深效果等可量化指标进行分析，并结合原始意图评估目标达成情况。

### FR-12｜自然语言局部调整
用户可以在当前方案基础上提出调整；系统应只修改相关目标，并尽量保留其他已确认目标。

### FR-13｜参数调整稳定性
通过阈值、冷却时间、滞回机制和用户锁定状态，避免自动参数反复来回变化。

### FR-14｜拍摄方案保存与复用
用户可以保存自定义方案、重命名、删除和再次应用。方案应记录适用场景和能力限制。

### FR-15｜预设方案库
提供少量可理解的场景方案，例如“自然人像”“电影感人像”“暖调美食”等。预设不应冒充保证成片效果。

### FR-16｜手动控制与覆盖
用户可以在需要时手动调整系统开放的参数；手动覆盖后，系统应尊重用户设置，并允许恢复 AI 方案。

### FR-17｜用户偏好
允许保存用户偏好的色调、曝光倾向、构图风格等非敏感偏好，并提供清除入口。

### FR-18｜隐私与数据控制
默认在设备端处理实时画面与照片。若调用云端决策服务，应说明传输的数据类别、用途，并提供可控选项。

### FR-19｜模型可用性与降级
本地模型不可用时，应用应退化到预设方案、规则引擎或基础相机能力，不得阻断基本拍摄。

### FR-20｜设备兼容性
根据系统版本和设备能力动态启用功能，并向用户说明不支持的功能。

### FR-21｜拍摄会话状态管理
支持从需求解析、方案生成、待应用、取景、拍摄、结果评估到调整的状态流转；中断后可安全恢复或结束会话。

### FR-22｜错误处理
对权限拒绝、相机被占用、参数设置失败、模型不可用、网络超时等情况给出清晰提示和恢复路径。

### FR-23｜方案版本与调整历史
在当前会话中记录方案版本和用户调整，支持撤销最近一次 AI 调整。

### FR-24｜基础无障碍
支持动态字体、足够对比度、VoiceOver 标签和不只依赖颜色传达状态。

### FR-25｜反馈入口
用户可对方案效果选择满意/不满意，并标注主要问题，为产品评估提供经授权的匿名统计数据。

### FR-26｜基础埋点
记录关键漏斗和性能指标，避免采集不必要的原始照片、音频或精确位置。

### FR-27｜首次使用引导
简要说明产品能力边界、相机权限和本地处理原则，并通过示例帮助用户理解自然语言拍摄。

### FR-28｜帮助与限制说明
对无法直接控制的成像效果、镜头限制和环境限制提供上下文说明。

### FR-29｜实时取景状态评估
在取景过程中按需评估当前画面是否偏离用户目标，并生成有限、可解释的调整建议。

### FR-30｜拍摄效果反馈迭代
拍摄后将图像分析结果与用户意图对照，支持“保留原目标、只调整指定项”的迭代流程。

### FR-31｜拍摄方案设备适配
同一意图在不同设备上映射到各自支持的参数与策略；不支持的目标应降级或说明。

### FR-32｜一键拍摄模式
对于用户已确认的简单方案，支持快速应用并进入取景拍摄；用户可随时退出自动辅助。

## 5. 非功能需求（NFR）

### NFR-01｜可靠性
相机核心链路不得依赖云端模型；云服务失败不得阻断基础拍照。

### NFR-02｜响应性
自然语言解析和方案生成需达到可接受的交互响应；具体 P50/P95 目标在真机基准测试后确定。

### NFR-03｜稳定性
参数更新不得导致持续抖动；相机配置失败应回退到上一个有效状态或安全默认状态。

### NFR-04｜隐私
遵循最小化采集原则；默认不上传原始照片和实时视频。云端请求应尽可能只包含必要的结构化状态。

### NFR-05｜能耗与热管理
实时分析按需触发；监测长时间取景、模型推理和图像处理的功耗及温升。

### NFR-06｜可维护性
意图 Schema、规则库、设备能力映射、模型适配器和相机执行层应模块化、可测试、可版本化。

### NFR-07｜可解释性
方案至少展示关键策略与重要限制，避免把模型置信度包装成成片成功保证。

### NFR-08｜安全性
参数执行前进行白名单、范围、能力和状态校验；所有云端密钥仅保存在服务端。

## 6. MVP 范围

### 6.1 MVP 纳入
- iOS 独立相机应用。
- 自然语言输入与结构化意图解析。
- 人像场景优先。
- 设备能力检测。
- Vision 人脸/主体基础分析。
- 摄影规则引擎与参数校验。
- 方案预览、应用、拍照和预览保存。
- 基础拍摄后分析。
- 自然语言局部调整。
- 少量预设方案与方案复用。
- 本地优先与降级路径。

### 6.2 暂缓
- 复杂夜景自动摄影。
- 专业级视频控制。
- 多人复杂构图自动决策。
- 大规模摄影风格市场。
- 生成式照片编辑与社交社区。
- JEV 成为必需依赖的正式功能。

### 6.3 JEV 实验范围
仅作为可选对照实验：针对复杂场景策略选择、目标冲突权衡和失败诊断，比较加入 JEV 前后的实际收益。

## 7. 核心指标

### 用户价值指标
- 首次拍摄满意度。
- 从描述需求到完成拍摄的耗时。
- 平均重拍/调整次数。
- 拍摄任务完成率。
- 方案复用率与 7/30 日留存。
- 用户主动反馈的“比原生相机更省事”比例。

### 技术指标
- 意图解析准确率与 Schema 合规率。
- 参数应用成功率、设备适配成功率。
- 自动对焦/曝光目标达成率。
- 模型不可用率与降级成功率。
- 实时分析延迟、能耗、温升。
- 云端 JEV 调用延迟、失败率与单次成本（仅实验组）。

### 目标设定原则
当前不预设未经真机和用户测试支持的数值门槛。先建立基线，再确定可验证的目标值。

---

## 8. 发布与验证计划

1. **技术 Spike**：验证目标设备的本地模型可用性、相机 API 控制边界、Vision 能力与功耗。
2. **人像闭环原型**：跑通意图—分析—方案—执行—拍摄—反馈。
3. **小规模可用性测试**：与原生相机对照，观察耗时、满意度、失败原因和复用意愿。
4. **JEV 对照实验**：仅在复杂策略任务中评估增益。
5. **MVP 迭代**：根据实测结果决定扩展场景与商业模式。

---

## 9. 主要风险与应对

| 风险 | 应对 |
|---|---|
| 本地模型在目标设备上的能力/可用性未确认 | 运行时检查，先做真机 Spike |
| 系统相机能力存在边界 | 公开 API 能力清单与设备适配层 |
| 模型输出不稳定 | Schema、规则引擎、回归测试集 |
| 自动调整干扰用户 | 用户锁定、撤销、冷却机制 |
| 审美难以客观量化 | 分场景目标指标 + 用户反馈 |
| 云端 JEV 增加延迟与成本 | 可选调用、超时降级、对照实验 |
| 用户价值不足以支撑付费 | 原型阶段验证频率、留存与付费意愿 |

---

## 10. 验收标准（MVP）

- 用户可输入一条中文拍摄需求，并得到符合 Schema 的结构化意图。
- 系统能识别设备能力，并拒绝或降级不支持的参数。
- 人像基础场景可以生成、预览并应用拍摄方案。
- 用户可以完成拍照、预览、保存和重拍。
- 用户可以通过自然语言提出局部调整，且系统保留未修改的目标。
- 模型或网络不可用时，基础拍摄仍可使用。
- 参数执行失败有明确提示和恢复路径。
- 能记录核心漏斗、错误、性能与用户反馈指标。
