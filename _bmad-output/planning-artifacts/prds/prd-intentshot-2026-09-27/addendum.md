## §B JEV 对照实验设计（自 v1.0 §6.3/§7/§8.4/§9 归并）

**定位**：复杂、低频、结构化策略判断的可选云端增强（内部代号，含义待确认 `[A-2]`）。不是相机控制器，不直接计算快门/ISO 数值，不作为基础拍摄依赖。

**适用**：候选策略比较、多目标冲突下的策略选择、复杂失败诊断路径。**不适用**：每帧实时分析、直接参数计算、AVFoundation 控制。

**服务边界**：`iOS App → IntentShot Backend → JEV API`。Backend 负责鉴权、配额、限流、超时、缓存、审计与密钥管理；客户端不持有服务密钥；只传脱敏后的结构化特征（场景类别、目标、候选策略、约束），默认不上传原始图像/视频。结果只在候选策略范围内经本地 Schema 与规则校验后采纳；置信度不得当作实际正确率。超时/失败时本地规则直接接管。

**A/B 设计**：A = 本地模型 + Vision + 规则引擎；B = 同架构 + 仅复杂策略任务调用 JEV。

**指标**：策略正确率、参数可执行率、目标达成度、用户满意度、拍摄耗时、延迟、失败率、单位成本（仅 B 组）。

**退出准则**（v2.0 新增，处置 rubric"无退出准则"）：
- **采纳条件**：复杂策略任务的策略正确率相对提升 ≥10%，且延迟增量与单次成本在 §9.2 设定的可接受区间内。
- **放弃条件**：增益 <10% 或成本/延迟不可接受 → 实验终止，JEV 不进入任何版本的主链路。
- 阈值细化随 §9.2 原型期确定并记录 memlog。

## §C 被拒绝的备选方案（2026-09-27 决策记录）

1. **设备策略**：拒绝"不设机型门槛"（AI 定位对多数用户名不副实）与"Spike 后再定"（二义性仍无文档兜底）。采纳：锁定 Apple Intelligence 机型为主体验。
2. **承诺边界**：拒绝"砍掉不可控承诺"（卖点减弱过大）与"保留表述+免责"（验证报告指出的核心问题）。采纳：承诺分级 + 不可控改口。
3. **输入方式**：拒绝"语音纳入 MVP"（范围膨胀）与"保留口号+标注"（预期落差仍在）。采纳：文本输入 + 口号改"把想法，拍成画面。"
4. **调整模式**：拒绝"默认自动应用"（干扰风险高、防抖要求最严）与"仅建议不做自动"（智能感最弱且 FR-13/3.2 前提消失）。采纳：默认仅建议 + 设置可切换自动应用。

## §D 承诺分级表技术备注（配合 PRD §4，待 Spike 验证）

- 镜头光圈在 AVFoundation 中为只读硬件值，第三方无法在拍摄时控制虚化强度；"背景虚化"唯一公开路径是调用系统人像模式（虚化强度由系统计算摄影决定）。
- 系统夜景模式（Night mode）不对三方开放；"夜景纯净"只能给引导类辅助。
- "电影感/暖调"的公开手段 = 白平衡 gain（有硬件 min/max 范围）+ 曝光目标偏置组合近似。
- 深度数据（AVDepthData）在第三方拍摄会话中多数场景不可用 → FR-11 虚化目标常为 unknown，属预期行为而非缺陷。
- 以上逐机型差异以 Spike 的 Capability Matrix 为准（`[A-3]`）。
