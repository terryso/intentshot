## Overall verdict

这份 PRD 最站得住的是它的诚实边界：§1.4 产品边界主动声明"不承诺完全控制 iOS 原生相机的所有能力"，§7 明确"当前不预设未经真机和用户测试支持的数值门槛"，§8 用 Spike→原型→可用性测试的阶梯而非直接承诺，这些让它作为方向决策文档可信。风险在于两点：一是下游可用性明显弱于链顶文档所需——无 Glossary、关键范围决策所依赖的 "JEV" 全文从未定义、用户旅程只有一条无主角的线性主流程；二是若干场景级取舍（美食/旅行/夜景是否在 MVP 内）与 FR-12 与验收标准之间的口径差被静默处理。进 UX/架构拆解前需要补名词表、JEV 定义与 FR↔验收追溯，否则下游只能靠猜。

对抗性审查把图景进一步压暗，并升级出三项 critical：**价值主张与公开 API 边界正面冲突**——"背景虚化、暖调、景深"这些最有说服力的承诺效果恰好全部落在 §1.4 自己声明"不作保证"的计算摄影区域内，MVP 核心场景可能空转；**目标设备与最低系统版本从未定义**——无本地模型的设备上产品形态二义（极小存量 vs 降级链路成默认体验）；**全文档零数值门槛**——所有可判定性推迟到一个没有 go/no-go 判据与失败预案的 Spike 之后。两位审查者独立命中同一批问题（JEV 未定义、FR-11 评估语义、场景取舍静默处理），交叉验证了发现的可信度。作为愿景陈述干净克制，但作为驱动 UX / 架构 / epics 的决策文档，需先修复 critical 项再前进。

## Findings by severity

### Critical (4)

**[Downstream usability / Adversarial H-09] "JEV" 全文未定义**（§6.2, §6.3, §7, §8, §9）
一个承载暂缓决策、实验设计与成本指标的术语从未展开，无 Glossary；下游架构文档已在自行定义（"JEV 为可选决策增强服务"），两文档定义来源断裂。6.2"暂缓 JEV 成为必需依赖的正式功能"等于给一个不存在的东西办暂缓手续，是早期草案的残迹。
Fix: 首次出现处展开全称并建立 Glossary 词条，注明其与本地模型/规则引擎的关系；重写 6.2 该条为正向表述；或把 6.3/8.4 整体移入附录实验计划。

**[Adversarial C-01] 价值主张与公开 API 能力边界正面冲突**（1.1 / 1.3 / 1.4 / 2.2，对照 NFR-08、FR-08、FR-31）
"背景虚化、暖调、景深"这些最有说服力的承诺效果，恰好全部落在 §1.4 自己声明"不作保证"的计算摄影区域内：AVFormation 公开 API 中镜头光圈只读、人像虚化与夜景模式依赖系统计算摄影链路、"电影感/暖调"只剩白平衡增益的有限调节。MVP 核心场景可能空转。
Fix: 增加"承诺效果 × 公开 API 手段 × 可控程度"对照表；据此裁剪 2.2 场景列表与第 10 节验收；把"哪些效果做不到"从免责条款升级为明确的产品决策。

**[Adversarial C-02] 目标设备与最低系统版本从未定义**（全文；8.1；6.1；FR-05/FR-19/FR-20）
PRD 通篇只说"本地模型"，从未出现 Foundation Models、最低 iOS 版本或目标机型集合。锁定 Apple Intelligence 机型则存量极小；不设限则降级链路成默认体验——产品实际形态是模板相机，"AI 智能相机"定位对多数用户是虚假宣传。
Fix: 明确最低 iOS 版本与目标机型集合（可以是"Spike 待定参数"形式）；写明不满足条件设备是"不支持安装"还是"降级可用"；点名核心技术依赖及其设备门控条件。

**[Adversarial C-03] 全文档零数值门槛，可判定性推迟到没有退出判据的 Spike 之后**（5 NFR-02/NFR-05；7；8；9）
NFR-02"可接受的交互响应"是自我引用。全文档没有任何可判定通过/失败的量化标准。Spike 本身没有 go/no-go 判据、时限、失败预案——若结论是"本地模型解析质量不够"，没有计划 B。下游性能故事与验收将全部写成"待真机后确定"。
Fix: 为 Spike 定义 go/no-go 判据与时限（临时门槛，标注可修订）；给 NFR-02/05 设临时量级；增加"Spike 失败决策树"；给第 8 节各阶段补退出条件。

### High (9)

**[Done-ness clarity] FR-11 "目标达成"评估语义未定义**（FR-11, §3.1 步骤8）
意图属性到可测量图像指标的映射规则、达成度的计算与呈现形态均缺失；这是产品闭环的核心环节，下游架构与故事创作无法从这里起步。
Fix: 为每类意图属性定义度量方式与判定阈值来源，写明反馈 UI 呈现的最小信息集。

**[Downstream usability] 无 Glossary 且核心名词语义漂移**（FR-02 vs FR-11/FR-12/§10）
"目标"在意图对象字段义与用户意图整体义之间摇摆；"意图/拍摄意图/结构化意图/摄影意图对象"变体并存。
Fix: 建 Glossary，固定"意图（Intent）"为对象、"目标（Objective）"为字段，全文替换统一。

**[Adversarial H-04] 主流程旗舰示例是产品自己承认可能做不到的指令，且混淆"参数调整"与"构图引导"**（3.1 步骤 9；FR-12；FR-02；对照 UI-UX 3.8）
"背景再暗一点"是 UI-UX 3.8 承认的物理难题；"人物往中间一些"不是相机参数而是构图引导。参数类/模式类/构图引导类三类输出物被揉成一个"局部调整方案"，epic 拆分时会当场爆炸。
Fix: 建立调整对象类型学，FR-12 明确每类输出物与验收差异；主流程示例换成 API 边界内可兑现的指令。

**[Adversarial H-05] 验收标准只验流程不验结果，且与 MVP 纳入清单、FR 体系不对齐**（10；对照 6.1、FR-14/15/16/17/23/24/27/28/32）
"应用"成功只说明参数写进去了，不说明照片达到用户描述的效果——照这 8 条验收，背景毫无虚化的成片也能让 MVP 通过。FR-16/17/23/24/27/28/32 全部不在验收清单内。
Fix: 验收改为结果导向（成片的可判定分级断言）；逐条核对 6.1 纳入项，要么补验收，要么显式声明不在验收范围。

**[Adversarial H-06] 核心指标几乎全部没有测量定义，部分无 FR 支撑，"匿名"与"留存"互相矛盾**（7；FR-25/FR-26；9）
"比原生相机更省事比例"无 FR 支撑；"意图解析准确率"无金标准语料；"拍摄任务完成率"的"任务"未定义；匿名统计与 7/30 留存口径不可兼得。FR-09/13/17/21/23/24/27/28/32 无任何指标验证。
Fix: 为每个指标写测量定义、数据来源、决策用途；补 FR 或砍指标；建标注集立项；明确伪匿名 ID 方案。

**[Adversarial H-07] 实时取景调整是"自动应用"还是"仅建议"：FR-29、FR-13 与体验原则三方打架**（FR-29 / FR-13 / FR-16；3.2；对照 UI-UX 3.6）
FR-29 说"建议"，FR-13 的防抖以自动应用为前提，3.2 体验原则确认自动应用存在。最核心的拍摄中交互模式没有答案——这直接决定取景器交互设计、防抖作用对象、撤销语义。
Fix: 明确默认模式（仅建议 / 自动应用+一键撤销 / 混合可切换），写清作用参数范围与 FR-16 锁定的优先级关系。

**[Adversarial H-08] 品牌口号承诺语音，MVP 只有打字**（1.3；FR-01；3.1）
口号"说出你想拍的" vs FR-01 白纸黑字"文本输入；后续可评估语音输入"。单手举机、户外阳光下用中文键盘输入长句是全流程最大摩擦点，品牌每天在承诺相反的东西。
Fix: 三选一：(a) 最小语音输入纳入 MVP；(b) 口号降级为"写下你想拍的"；(c) 明确 MVP 仅文本且引导/商店素材不得暗示语音。

**[Adversarial H-10] UI-UX 设计了"作品"一级导航，PRD 无任何 FR 支撑；视频口径两文档不一致**（跨文档：PRD 第 4 节/6.1；UI-UX 2、3.10、3.9）
UX 文档画出了比 PRD 范围更大的产品：作品页无 FR 覆盖、UI-UX 作品页含视频而 PRD 暂缓视频。epic 规划照 UI-UX 拆会无中生有一整页功能，照 PRD 拆会砍掉已设计好的一级导航。
Fix: PRD 补作品页最小 FR 或 UI-UX 显式标注非 MVP；统一视频与夜景口径。

**[Scope honesty] 场景级去范围未显式化**（§2.2 vs §6.2）

**[Downstream usability] 无具名主角的情景旅程**（§3.1）

**[Downstream usability] §6.1 与 §10 无 FR 引用**（§6.1, §10）
验收八条与 MVP 纳入清单均为散文，无法追溯覆盖/遗漏（如 FR-24 无障碍不在任何验收条目）。

**[Adversarial M-11] MVP 边界自相矛盾："人像优先" vs "暖调美食"预设 vs 2.2 四大场景**（6.1；FR-15；2.2）

**[Adversarial M-13] 只能撤销一次的"历史"是装饰**（FR-23；FR-30；FR-16；3.1）

**[Adversarial M-14] FR-11 评估器自身正确性无校准计划，风险应对循环论证**（FR-11；9）

Fix: 首版指标收窄为算法定义明确的项；安排小规模人工标注校准。

**[Adversarial M-15] "不得导致持续抖动"没有测度，Spike 不覆盖稳定性调参**（NFR-03；FR-13；8.1）
抖动无定义、防抖参数全未定、Spike 与原型清单均不含稳定性调参——用未验证的机制缓解未定义的问题。
Fix: 给抖动可测定义；防抖调参列入 8.2 原型验证范围。

**[Adversarial M-16] 目标市场、合规与上架要求整体缺席**（全文；FR-01；FR-25/26；9）
首发市场（大陆/港台/海外）未定，直接决定合规要求；风险表提"付费意愿"但全文无商业假设。
Fix: 增加目标市场与合规清单小节；一句话写下商业假设及验证方式。
