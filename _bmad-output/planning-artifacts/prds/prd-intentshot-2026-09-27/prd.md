## 1. 产品概述

### 1.1 一句话定义

意拍是一款自然语言驱动的 AI 智能相机：用户**写下**想拍出的画面，应用结合设备能力与现场环境，自动生成并应用拍摄方案，帮助用户更容易拍出接近预期的照片。

### 1.2 产品愿景

降低摄影参数和拍摄技巧的门槛，让用户把注意力放在"想拍什么"与"如何构图"上，而不是研究复杂的相机设置。

### 1.3 核心价值主张

> **把想法，拍成画面。**（英文：Turn your idea into a shot.）

> ⚠️ 口号已从 v1.0 的"说出你想拍的，剩下的交给意拍"变更：MVP 仅支持文本输入，口号不得承诺输入方式。`BRAND.md` 需同步更新（见 §14 Open Questions Q4）。

产品形成"意图理解—场景分析—相机配置—实际拍摄—效果反馈"的闭环。核心承诺实行**分级制**（见 §4）：可以控制的效果明确承诺，不能控制的效果如实说明并给出替代路径，不用免责声明掩盖承诺落空。

### 1.4 产品边界

- 意拍是独立相机应用，不是通用 AI 助手。
- 首期重点是拍摄前和拍摄中的相机配置与辅助，不承诺完全控制 iOS 原生相机的所有能力（承诺边界见 §4 分级表）。
- 系统只使用公开、可用的 API 和设备运行时能力；**凡 §4 标注"不承诺"的效果，产品文案、引导与商店素材均不得暗示可达成**。
- 生成式后期编辑、社交社区、完整专业视频制作不属于 MVP 核心范围。

### 1.5 目标设备与系统要求 `[决策 C-02]`

- **主体验机型**：支持 Apple Intelligence 的 iPhone（预期 iPhone 15 Pro 及更新机型），最低系统 iOS 26。`[A-1]`
- **其他设备**：可安装，进入**降级形态**（基础相机 + 规则策略 + 预设方案，见 FR-19）。降级形态不作为核心目标体验，不做获客投放；App Store 页面明确标注设备与系统要求。
- 设备门控的具体机型清单与系统能力以 §9.1 Spike 的 Capability Matrix 验证结果为准。

### 1.6 术语表（Glossary）

| 术语 | 定义 |
|---|---|
| **意图（Intent / CaptureIntent）** | 自然语言解析出的结构化意图对象，字段：主体、风格、**目标**、优先级、约束、不确定项、构图（可选）。全文统一用"意图"指代该对象，不再使用"拍摄意图/结构化意图/摄影意图对象"等变体。 |
| **目标（Objective）** | 意图对象的**子字段**，指对画面效果的单一期望（如"脸部明亮"）。全文中"目标"仅作此解；指用户整体诉求时用"意图"。 |
| **拍摄方案（Plan / CapturePlan）** | 设备可执行的策略集合（模式、镜头、对焦/曝光/色彩策略、限制说明）。 |
| **建议（Suggestion）** | 取景过程中系统给出的可点击调整卡片。默认交互模式下，建议是实时调整的唯一形态（FR-29）。 |
| **局部调整（Adjustment）** | 在当前方案基础上的修改，分三类（FR-12）：**参数类**（改参数值）、**模式类**（切换拍摄模式）、**构图引导类**（仅输出引导，不改任何相机状态）。 |
| **降级（Fallback）** | 四级降级链（FR-19）：①本地模型+Vision+规则 → ②预设+Vision+规则 → ③纯规则辅助 → ④基础相机。 |
| **JEV** | 云端决策增强服务的内部代号（字面含义待确认 `[A-2]`）。角色：复杂、低频策略判断的**实验性**增强（§7.4），不是相机控制器，不是基础拍摄的依赖。 |
| **伪匿名 ID** | 用户授权统计后生成的随机标识符，可随时清除，用于留存类统计（FR-26）。与"匿名"的口径差异见 §8.1。 |

## 2. 用户与使用场景

### 2.1 目标用户

1. **日常拍摄用户**：知道想要什么效果，但不了解曝光、对焦、镜头等参数。
2. **轻度摄影爱好者**：希望更快获得稳定效果，不想每次从头调参。
3. **内容创作者**：需要反复拍摄人像、美食、产品或生活场景，希望保存和复用方案。

> §1.5 之外的降级设备用户**不是**核心目标用户；其可用性目标是"能完成基本拍摄"，不承诺 AI 体验。

### 2.2 核心场景与版本归属 `[修订：场景取舍显式化]`

| 场景 | 版本归属 | 说明 |
|---|---|---|
| 人像（含逆光人像） | **MVP** | 唯一首发场景，验收覆盖 |
| 美食/静物 | P1 | 仅在场景感知能力就绪后开放；"暖调美食"预设移出 MVP 预设白名单（FR-15） |
| 旅行与风景 | P1 | v1.0 无任何 FR 覆盖，如实标注而非静默 |
| 夜景 | P1（简单夜景）/ 暂缓（复杂夜景自动摄影） | 系统夜景模式不对三方开放（§4），仅可做引导类辅助 |
| 视频 | 暂缓 | 不作为任何版本的核心承诺 |

### 2.3 Jobs To Be Done

> 当我想拍出某种效果、却不知道相机该怎么设置时，我希望只需写下想拍的画面，应用就能帮我配置相机并指导我完成拍摄，让我更少试错地获得满意照片。

### 2.4 用户旅程 `[新增：具名主角旅程]`

**UJ-1｜小雨（日常拍摄用户）·人像主流程**
小雨在咖啡店想给朋友拍张"脸部亮一点、背景虚化"的照片。她打开意拍，在输入框写下这句话，两秒后看到方案卡："人像模式 · 优先脸部曝光"。点击应用，取景器顶部出现"方案已应用"标签。她构图时弹出一张建议卡："人物偏暗，点击提高脸部亮度"。她点了，快门。结果页显示：脸部明亮 ✓、背景虚化 ✓（系统人像模式）。她保存了照片。

**UJ-2｜阿哲（内容创作者）·冲突需求与澄清**
阿哲输入："晚上室内拍菜品，要无噪点、不用闪光灯、每张都清晰。"系统检测到硬冲突（暗光+无闪光+高快门互相矛盾），且他的描述没有给优先级，弹出**澄清卡**："暗光下无法同时保证零噪点和高速快门——更在意画面干净还是不怕手抖？"阿哲选了"画面干净"。方案生成：降快门 + 提示稳定持机 + 白平衡偏暖。他接受折中，并在结果页看到"清晰度：部分达成"的如实标注。

**UJ-3｜老周（轻度摄影爱好者）·降级场景**
老周的机型不在主体验名单。打开意拍后引导页说明："你的设备支持基础智能辅助。"他选择"自然人像"预设，应用后相机完成可支持的配置（对焦、曝光倾向），页面明确显示"AI 方案生成在此设备不可用，已启用规则策略"。他正常完成拍摄，没有被打断。

## 3. 产品体验与用户旅程原则

### 3.1 主流程 `[修订：示例可兑现、输入改文本、调整改建议卡]`

1. 打开意拍，进入取景器。
2. 点击"描述想拍的画面"或选择一个场景预设。
3. **文本输入**自然语言，例如："拍一张人物清晰、脸部亮一点、画面偏暖的人像。"
4. 应用解析意图，结合设备能力和实时画面生成拍摄方案。
5. 用户查看方案摘要，点击"应用方案"。
6. 进入取景器，系统**一次性**执行可支持的参数配置并显示应用结果（成功/部分/失败逐项标注）。
7. 用户构图并按下快门。
8. 应用展示照片及逐目标达成反馈（FR-11 的最小信息集）。
9. 用户可点选建议卡继续调整，例如"脸部再亮一点"（参数类）或获得"人物往中间一些"的构图引导（引导类，见 FR-12 类型学）；**默认模式下系统不自动改参数**。
10. 用户保存照片，并可保存或复用拍摄方案。

### 3.2 关键体验原则

- 用户始终可以拍摄，不被 AI 流程锁死。
- **方案应用是一次性的自动配置；取景中的实时调整默认为"仅建议"（FR-29），用户可在设置中切换为"自动应用+一键撤销"** `[决策 H-07]`。
- 自动调整要可感知、可撤销，避免参数无提示地跳动。
- 用户明确锁定的参数和目标，不应被系统随意覆盖；锁定优先级高于一切自动/建议行为。
- 复杂或互相冲突的需求应按 FR-03 的触发规则澄清或折中，并解释限制。
- 取景器是核心工作区，AI 对话不应长期遮挡画面。

## 4. 承诺效果与可控性分级 `[新增，处置 C-01]`

**原则**：用户语言的效果必须映射到公开 API 的实现手段并标注可控性；"承诺级"效果进入验收（§11），"不承诺"效果不得出现在营销与引导文案中。

| 效果（用户语言） | 公开 API 实现手段 | 可控性 | 承诺等级 |
|---|---|---|---|
| 主体清晰 | 对焦策略（连续 AF、点选 AF、主体优先） | 高 | **承诺级** |
| 脸部明亮 | 曝光补偿 / 曝光目标偏置（人脸加权） | 高 | **承诺级** |
| 画面偏暖/偏冷 | 白平衡 gain 调节 | 中（有硬件范围） | **承诺级**（范围内） |
| 背景虚化 | 调用系统人像模式 | 低-中（虚化强度不可控） | **改口承诺**："使用系统人像模式获得虚化，虚化强度由系统决定" |
| 夜景纯净/长曝光 | 系统夜景模式不对三方开放 | 不可控 | **不承诺**；仅提供拍摄引导（稳定持机、利用光源） |
| 电影感 | 白平衡 + 曝光组合的有限近似 | 中 | **改口承诺**："偏暖色调 + 保护高光的曝光倾向" |
| 构图改善 | 网格线、主体位置提示、裁切建议 | 引导类 | **仅引导**，不改变画面 |

`[A-3]` 各机型具体能力边界以 Spike 产出的 Capability Matrix 为准；本表为 MVP 缺省判定。

## 5. 功能需求（Functional Requirements）

> FR-01 至 FR-32 编号与 v1.0 一致；标注 `[v2 修订]` 的条目含实质性变更。

### FR-01｜拍摄需求输入 `[v2 修订：H-08]`
用户通过**文本输入**描述想拍的画面；系统支持中文常见摄影表达。MVP 不含语音输入；语音输入列 P1 候选（§14 Q3）。引导文案与商店素材不得暗示语音能力。

### FR-02｜意图结构化
将自然语言转换为统一的意图（Intent）对象，字段：主体、风格、目标、优先级、约束、不确定项，以及**可选的构图字段**（如居中/三分法）。输出必须通过 Schema 校验。术语遵循 §1.6。

### FR-03｜需求冲突识别 `[v2 修订：M-12]`
识别无法同时满足的目标。**触发规则**：目标间存在硬冲突、且意图中用户优先级缺失或互相矛盾时，触发澄清（单一问题卡，见 UJ-2）；优先级明确时直接生成折中方案并解释取舍。不再使用"或"字式无约束表述。
**验收锚点**：对金标准冲突用例集 `[A-4]`，澄清/折中路径选择正确且解释完整。

### FR-04｜场景与主体分析
分析实时取景中的人物、主体位置、亮度、逆光和构图信息。轻量指标（亮度、运动）低频连续获取；重型分析（分割、场景分类）**在方案生成时与建议触发时**按需运行，不逐帧运行。

### FR-05｜设备能力识别
运行时读取当前设备和拍摄会话支持的镜头、模式及参数能力，形成 Capability Matrix。不得将某一机型的能力写死为所有设备通用。

### FR-06｜拍摄方案生成
根据意图、场景状态、设备能力和 §4 分级表生成方案，方案需说明目标、模式、镜头策略、对焦/曝光策略及限制。**§4 中"不承诺"的效果不得出现在方案的可执行项中，只能出现在限制说明里。**

### FR-07｜方案预览与应用
用户查看方案摘要后应用。系统逐项显示应用成功、部分应用或无法应用。

### FR-08｜相机参数执行
通过公开相机 API 应用设备支持的参数。所有参数经过白名单、范围、模式兼容性和安全约束校验。

### FR-09｜取景器与构图辅助 `[v2 修订：量词收敛]`
提供取景画面、主体提示和构图辅助。辅助项可枚举：网格线、主体位置提示、水平仪，均默认可关闭；方案状态以小型标签显示。

### FR-10｜拍照与预览
支持拍照、预览、重拍、保存和进入系统照片库（权限按系统要求申请）。MVP 不含应用内作品页（`[A-9]`）。

### FR-11｜拍摄后质量分析 `[v2 修订：high，评估语义落地]`
**度量映射表**：

| 目标类型 | 度量方式 | 数据来源 | 已知局限 |
|---|---|---|---|
| 脸部明亮 | 人脸区域亮度达到场景校准阈值 | Vision 人脸检测 + 图像分析 | 极端逆光可能误判 |
| 主体清晰 | 主体区域清晰度代理（梯度方差） | Vision 主体分割 | 代理指标，非主观清晰度 |
| 背景虚化 | 有深度数据：前后景深度差；无深度数据：**unknown** | AVDepthData（可用时） | 多数三方拍摄无深度数据 |
| 画面偏暖 | 平均色温相对目标区间 | 图像分析 | — |
| 构图 | 规则类检查（居中/三分线邻近） | Vision 主体位置 | 仅规则类，无美学判断 |

达成度四态：achieved / partial / not-achieved / unknown。**反馈 UI 最小信息集**：每个目标一行（名称 + 状态 + 一句解释），不提供单一总分（NFR-07）。评估器自身的校准计划见 §9.3 与 §8.1 指标"评估一致率"。

### FR-12｜局部调整 `[v2 修订：high H-04，类型学]`
局部调整分三类，输出物与验收不同：
1. **参数类**（如"脸部再亮一点"）：修改 CapturePlan 的参数字段，走 FR-08 校验后应用。
2. **模式类**（如"背景虚化"）：切换拍摄模式（启用人像模式），提示模式切换的副作用。
3. **构图引导类**（如"人物往中间一些"）：**仅输出引导**（网格/箭头提示、快门时机建议），不修改任何相机状态。
任何调整只修改相关目标；除用户指定修改项外，其余目标字段值保持不变（与 §11 验收口径一致）。

### FR-13｜参数调整稳定性 `[v2 修订：量化口径]`
自动应用模式下（设置开启后），防抖机制生效：阈值、冷却时间、滞回。**量化口径**：60 秒窗口内同一参数的自动变更 ≤3 次，且不出现方向交替震荡（初值，`[A-10]` 真机校准）。建议模式下防抖作用于建议触发频率。

### FR-14｜拍摄方案保存与复用
保存自定义方案、重命名、删除和再次应用。方案记录适用场景和能力限制。

### FR-15｜预设方案库 `[v2 修订：M-11，白名单]`
**MVP 预设白名单为 3 个人像变体**："自然人像""电影感人像""逆光人像"。预设文案不得承诺成片效果。"暖调美食"等非人像预设移入 P1（§7.2）。

### FR-16｜手动控制与覆盖
用户可手动调整系统开放的参数；手动覆盖后系统尊重用户设置，并允许恢复到最近的 AI 方案版本（与 FR-23 撤销栈的关系：恢复 = 撤销栈回退到最近一次 AI 版本）。锁定优先级最高。

### FR-17｜用户偏好
保存色调、曝光倾向、构图风格等非敏感偏好，提供清除入口。

### FR-18｜隐私与数据控制
默认在设备端处理实时画面与照片。若调用云端决策服务（仅限 §7.4 实验），说明传输的数据类别、用途，并提供可控选项。

### FR-19｜模型可用性与降级 `[v2 修订：C-02 联动]`
本地模型不可用时按 §1.6 降级链退化：预设方案 + 规则引擎 → 纯规则辅助 → 基础相机。降级不阻断基本拍摄。降级形态明确告知用户（见 UJ-3），且不属于核心目标体验（§1.5）。

### FR-20｜设备兼容性 `[v2 修订：门控]`
按 §1.5 门控：不满足主体验条件的设备进入降级形态并如实说明。功能随系统版本和设备能力动态启用。

### FR-21｜拍摄会话状态管理
支持 `intent_input → intent_parsed → scene_analyzing → plan_ready → applying → ready_to_capture → capturing → evaluating → adjustment_ready / completed` 状态流转（架构细节见 ARCHITECTURE.md §3.2）；中断后可安全恢复或结束会话。

### FR-22｜错误处理
对权限拒绝、相机被占用、参数设置失败、模型不可用、网络超时给出清晰提示和恢复路径。

### FR-23｜方案版本与调整历史 `[v2 修订：M-13，撤销深度]`
会话内记录方案版本与用户调整。**撤销深度：栈式撤销全部 AI 调整，至少支持连续撤销最近 5 步**；用户手动调整不进入 AI 撤销栈（用 FR-16 恢复）。

### FR-24｜基础无障碍 `[v2 修订：标准引用]`
支持动态字体、VoiceOver 标签、不只依赖颜色传达状态；文字对比度不低于 WCAG AA（4.5:1）。

### FR-25｜反馈入口 `[v2 修订：统计单位]`
用户对方案效果选择满意/不满意并标注主要问题。**满意度统计单位 = 会话**（首次拍摄满意度 = 首次会话内对首张保存照片的评价）。数据经授权收集，采用伪匿名 ID（§8.1）。

### FR-26｜基础埋点 `[v2 修订：事件枚举与标识方案]`
核心漏斗事件：`intent_submitted / plan_generated / plan_applied / shutter_released / photo_saved / adjustment_applied / suggestion_shown / suggestion_accepted / assist_toggled`。性能事件：解析、生成、应用三段分段耗时。**标识方案**：统计授权后生成伪匿名 ID（随机、可清除），留存统计仅使用伪匿名 ID；未授权用户不进入留存统计。不采集原始照片、音频或精确位置。

### FR-27｜首次使用引导 `[v2 修订：H-08 联动]`
说明产品能力边界（含 §4 分级）、相机权限、本地处理原则和**文本输入方式**；示例不得演示语音输入。

### FR-28｜帮助与限制说明
对无法直接控制的成像效果（§4"不承诺"项）、镜头限制和环境限制提供上下文说明。

### FR-29｜实时取景建议 `[v2 修订：high H-07，默认模式落地]`
**默认模式 = 仅建议**：取景中系统通过建议卡提出调整，用户点击后才应用。**触发时机**：方案应用后首次稳定评估、构图显著变化、光线显著变化（阈值待真机校准）；**单次建议 ≤2 条**；建议卡可整体关闭。**设置项**："自动应用 + 一键撤销"模式（开启后 FR-13 防抖生效，FR-16 锁定仍然优先）。

### FR-30｜拍摄效果反馈迭代 `[v2 修订：分工]`
拍摄后评估（FR-11）与用户意图对照，会话进入"评估后迭代"状态；此状态下的调整走 FR-12 类型学流程。FR-30 的独有职责 = 状态转换与"保留原目标、只调整指定项"的迭代约束；图像分析归 FR-11，调整执行归 FR-12。

### FR-31｜拍摄方案设备适配
同一意图在不同设备上映射到各自支持的参数与策略；不支持的目标按 §4 分级降级或说明。

### FR-32｜一键拍摄模式 `[v2 修订：判据]`
**进入判据**：当前方案曾成功应用至少一次，且当前无未解决的冲突目标。满足时方案卡提供"快速应用"入口，跳过摘要确认直达取景；用户可随时退出自动辅助。

## 6. 非功能需求（NFR）

### NFR-01｜可靠性
相机核心链路不得依赖云端模型；云服务失败不得阻断基础拍照。

### NFR-02｜响应性 `[v2 修订：C-03，临时门槛]`
**临时门槛**（初值 `[A-6]`，Spike 校准后修订）：意图解析 + 方案生成端到端 P50 ≤3 秒、P95 ≤8 秒（主体验机型真机）。**分解口径**：解析、生成、应用三段分别埋点（FR-26）。测定时点：§9.1 Spike 产出基线，§9.3 可用性测试后回填正式目标。

### NFR-03｜稳定性 `[v2 修订：M-15，抖动定义]`
**抖动定义**：60 秒窗口内同一参数自动变更 >3 次，或出现方向交替震荡（调大→调小→调大）。不满足即视为抖动缺陷。防抖参数调优列入 §9.2 原型验证范围。相机配置失败应回退到上一个有效状态或安全默认状态。

### NFR-04｜隐私
最小化采集；默认不上传原始照片和实时视频。云端请求只包含必要的结构化状态。统计标识仅用伪匿名 ID（FR-26）。

### NFR-05｜能耗与热管理
实时分析按需触发。**必测项**（Spike）：连续 10 分钟取景的耗电量、温升、是否触发系统降频；临时上限待实测基线后设定 `[A-6]`。

### NFR-06｜可维护性
意图 Schema、规则库、设备能力映射、模型适配器和相机执行层模块化、可测试、可版本化。

### NFR-07｜可解释性
方案与结果反馈展示关键策略、重要限制与达成状态；不提供单一"照片评分"，不把模型置信度包装成成片保证。

### NFR-08｜安全性
参数执行前进行白名单、范围、能力和状态校验；所有云端密钥仅保存在服务端。

## 9. 发布与验证计划 `[v2 修订：C-03，判据与退出条件]`

### 9.1 阶段一：技术 Spike（建议时限 2–3 周 `[A-6]`）
**Go/No-Go 判据**（初值，均可修订）：
1. Foundation Models 在主体验机型清单可用，意图解析临时门槛达标：P95 ≤8s、Schema 合规率 ≥95%、金标准集抽样准确率 ≥80%。
2. Capability Matrix 覆盖 §4 全部"承诺级"效果。
3. Vision 人脸检测在逆光/暗光样本集上可用。
4. 连续 10 分钟取景功耗温升有实测数据且无系统降频。

**Spike 失败决策树**：
- 解析质量不达标 → (a) 缩 MVP 至"预设 + 规则策略"形态重新定义价值；(b) 评估云端解析（触发 FR-18 隐私评审）；(c) 暂停立项。
- 相机能力覆盖不足 → §4 承诺表降级重排，重走承诺分级评审。
- 功耗不达标 → 下调分析频率/收窄触发条件后重测。

### 9.2 阶段二：人像闭环原型
跑通意图—分析—方案—执行—拍摄—反馈。**新增职责**：构建金标准语料 `[A-7]` 与冲突用例集 `[A-4]`；防抖参数调优（NFR-03）；FR-11 首版度量实现。

### 9.3 阶段三：小规模可用性测试
与原生相机对照：耗时、满意度、失败原因、复用意愿。**新增职责**：评估器人工标注校准（M-14）；定性访谈提纲含"比原生相机更省事吗"（§8.1 移入项）；**回填 §8 全部目标值**；验证付费意愿 `[A-8]`。

### 9.4 阶段四：JEV 对照实验
见 `addendum.md` §B；不通过则不进入默认链路（退出准则已定义）。

### 9.5 阶段五：MVP 迭代
根据实测结果决定扩展场景与商业模式。

## 11. 验收标准（MVP）`[v2 修订：H-05，结果导向 + FR 映射]`

1. 输入一条中文拍摄需求，产出 Schema 合法的意图对象。（FR-01/02）
2. 对冲突用例集 `[A-4]`，系统按 FR-03 规则正确选择澄清或折中，且解释完整。（FR-03）
3. 系统能识别设备能力，对不支持参数明确拒绝或降级并说明。（FR-05/31）
4. 人像场景可生成、预览并应用方案，逐项显示成功/部分/失败。（FR-06/07）
5. **效果断言**：在 ≥2 台主体验机型上，逆光人像场景 20 张样本中，"脸部明亮"达成 ≥70%、"主体清晰"达成 ≥70%、"画面偏暖"达成 ≥70%（口径按 FR-11 度量映射表；初值 `[A-5]` 待 §9.2 校准）。（FR-11）
6. 局部调整三类各至少 1 个用例通过，且未指定的目标字段值不变。（FR-12/30）
7. 连续 2 次 AI 调整后可逐步撤销，第 5 步内可回到任一历史版本。（FR-23）
8. 拍照、预览、保存、重拍全流程通过。（FR-10）
9. 断网且本地模型不可用时，基础拍摄 + 规则方案可用，降级状态如实提示。（FR-19/NFR-01）
10. 参数执行失败有明确提示并回退上一有效状态。（FR-08/NFR-03）
11. 手动覆盖后系统尊重用户设置，并可恢复最近 AI 方案；一键模式判据（FR-32）生效。（FR-16/32）
12. VoiceOver 可完成主流程；文字对比度 ≥4.5:1。（FR-24）
13. 引导与商店素材不含语音暗示，说明能力边界。（FR-27/28）
14. §8.1 核心事件全部上报，伪匿名 ID 可生成、可清除。（FR-26）
15. 预设白名单 3 个可应用，文案无效果承诺；方案可保存/复用/重命名/删除。（FR-14/15）
16. 偏好可保存、可清除。（FR-17）

**范围声明**：FR-21/22 的异常分支（权限拒绝、相机占用等）以 §9.2 原型期的用例通过为准，不单列 MVP 验收项。
